# ADR 0012 — API de contrôle : native et compat

- **Statut** : **accepté** le 2026-11-11 (réponses du mainteneur aux questions Q1, Q2, Q4, Q5,
  Q12, Q14 de [`phase-5.md`](../specs/phase-5.md))
- **Date** : 2026-11-11
- **Contexte** : BRIEF §2.2, §4 (Phase 5), §5, §6 (`axum`, `tokio`), §7 ; ADR 0003 (état et
  commandes) ; [`api-compat.md`](../specs/api-compat.md)

## Décision
1. **Crate `vma-api`**, sans dépendance au rendu ni à l'UI : elle reçoit un `CommandSender`
   (source `Api`) et un `StateReader` (instantané `Arc<State>` publié par `vma-control` à
   chaque changement). Elle ne modifie jamais l'état : tout passe par des `Command`,
   journalisées comme celles de l'UI.
2. **Runtime tokio à part**, deux threads (`vma-api`), démarré par `app/` ; un échec
   (port pris) ne fait pas échouer VMA : l'API est marquée indisponible, avec sa raison, dans
   l'UI. Aucun appel de l'API ne bloque `vma-control` : canal de commandes borné, refus
   « occupé » s'il est plein.
3. **Trois serveurs** : HTTP compat (8088), TCP compat (8099), API native HTTP + WebSocket
   (8090), ports réglables. **Écoute sur 127.0.0.1 par défaut** ; « accessible depuis le
   réseau » (0.0.0.0) est une case des Réglages, avec un avertissement : le protocole compat
   n'a pas d'authentification.
4. **`axum`** (MIT) pour HTTP et WebSocket ; serveur TCP écrit sur `tokio` (protocole ligne à
   ligne d'`api-compat.md` § 1) ; XML écrit avec `quick-xml` (MIT).
5. **Clients lents** : une file bornée par connexion ; si elle déborde, la connexion est
   fermée (le client se reconnecte) ; aucune donnée ne s'accumule sans limite.
6. **Identifiant de protocole** (Q1) : l'élément racine du XML d'état porte le nom de la
   référence en minuscules, exigé par les clients existants. Il est **une constante unique**
   de `api::compat`, jamais affichée dans l'UI, les messages ni la documentation utilisateur
   (« API compat »). C'est la seule exception à BRIEF §2.2, décidée par le mainteneur pour que
   Companion fonctionne sans modification.
7. **Version annoncée** (Q2) : une version 26 et une édition, constantes d'`api::compat`,
   fixées et documentées dans `api-compat.md` après l'observation du XML réel (Q3).
8. **Noms de fonction insensibles à la casse** ; `Input` = numéro, nom ou clé de l'input ;
   `Mix` = 0 seulement ; une fonction non prise en charge → `ER` (TCP) / 500 (HTTP) avec la
   raison.

## Alternatives écartées
- **API dans `vma-control`** : un client réseau pourrait retenir le thread qui applique les
  commandes.
- **`hyper` seul** : plus de code pour le routage et le WebSocket, sans gain.
- **Écoute sur le réseau par défaut** (comme la référence) : n'importe quel poste du réseau
  pourrait piloter l'émission sans que l'opératrice l'ait voulu.

## Conséquences
- Licences : `axum` et ses dépendances (`tower`, `hyper` : MIT) notées dans le `Cargo.toml`
  racine, `cargo deny` à jour.
- Les tests de conformité de l'API compat (un par fonction) et le rejeu du trafic du module
  Companion tournent en CI sans réseau extérieur (127.0.0.1).
